# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project

Night Watch is a browser text RPG set in an original low-fantasy north: a border fortress in snowy mountains. It began around 2019–2020 as a Game of Thrones fan game, and direct references to the show have since been removed (images, names, the Black Castle); keep new content free of them. The game is in two languages: Russian is primary (content is written in it, code comments are in Russian), English is a translation (see Languages); keep new player-facing text in Russian and add its English translation.

Stack: Vite, TypeScript (strict), Preact, Vitest, ESLint (typescript-eslint strict) and Prettier.

## Commands

```bash
npm run dev          # dev server at http://localhost:5173 (also defined in .claude/launch.json)
npm run build        # typecheck + production build into dist/
npm run check        # typecheck, lint, format check and tests: run before committing
npm test             # all tests once
npx vitest run tests/combat.test.ts   # one test file
npx vitest run -t "подлый удар"       # tests whose name matches
npm run format       # apply Prettier
```

In `npm run dev` a debug panel (`src/ui/debug/DebugPanel.tsx`, toggled by the 🛠 button or the ` key) offers the combat balance table (see Combat), a story map (`src/game/storyMap.ts`: scenes in columns by steps from the entry points — start, events, NPC talks, actions at points of interest — with their links; dead ends and unreachable scenes in red; click to jump), a quick start, a jump to any scene (applied like entering it: its `location` and `set` take effect) or to free roaming, a jump to any location, time skips (+1 h / +6 h, events fire as in play), resetting fired events, today's once-a-day activities and the visited marks, relation −/+ per character, flag toggles, hero HP/XP/stat/weapon/armor/item edits, an instant fight win and save deletion. It is rendered only under `import.meta.env.DEV`, so it isn't in production builds. Its transitions live in `src/game/debug.ts` and go through `store.apply()`, so autosave still applies; when adding a new kind of game state (time, locations), add a matching control there.

TypeScript is pinned to 6.0 because typescript-eslint doesn't support TypeScript 7 yet. If the dev server starts failing to resolve `@/…` imports after running tests alongside it, restart `npm run dev`.

Functions whose names start with `use` are treated as hooks by the react-hooks lint rules, so name non-hook helpers otherwise (`consumeItem`, `applyItem`).

## Architecture

Three layers, each depending only on the ones before it, plus translation (`src/i18n/`) between the game and the UI:

- **`src/content/`: data.** The story (`chapters/*.ts`, merged in `story.ts` with `START_SCENE`), locations (`locations.ts`: `LocationId` is a hand-written union because exits reference it), NPCs with schedules and journal descriptions (`npcs.ts`), relation limits and attitude names (`relations.ts`), story events (`events.ts`), the journal of goals and leads (`journal.ts`), the bestiary (`enemies.ts`), combat tuning numbers (`combat.ts`), hero classes, weapons, armors, items, stat names, portraits, progression (`progression.ts`: XP rewards, level thresholds, level-up rewards) and the registry of decision flags (`flags.ts`). Ids for flags, classes, weapons and items are derived from these registries (`keyof typeof …`), so a typo in a flag or class id is a compile error. A new flag must be added to `FLAGS` before use.
- **`src/game/`: pure logic, no DOM.** `types.ts` holds all shared types. `engine.ts` holds state transitions (`choose`, `fightAction`, `closeFight`, `startNewGame`, …) that take a `GameState` and return a new one without mutating it. `world.ts` (locations, NPC presence, events, time passing), `journal.ts` (the journal view and its change notices), `relations.ts` (changing relations, attitudes, the journal's people), `time.ts`, `combat.ts` (`playRound`, `combatStats`), `balance.ts` (the fight simulator behind the balance table), `checks.ts`, `hero.ts` (loot, items) and `progression.ts` (XP, levels) do the same for their parts; `context.ts` holds helpers shared by the engine and the world (`getScene`, `textContext`, `isAvailable`, `meetsCondition`) so they don't import each other, and `save.ts` holds the versioned save format. The game layer never builds player-facing strings: notices, the fight log, generated choice labels (moves, waiting, sleep) and reasons a choice or item is unavailable are `Message` descriptors (`{ id: 'xp', amount }`, see `types.ts`), which the UI formats in the player's language; a choice's `text` and `disabled` are a `Label` (content `Text` or a `Message`). Anything random takes an `Rng` (`() => number`) parameter instead of calling `Math.random`, which is how tests pin outcomes (`seededRng` in `random.ts` gives a reproducible one).
- **`src/ui/`: Preact.** `store.ts` wraps the engine: it holds the `GameState`, applies transitions and performs side effects: it autosaves after every change while in the story and not in a fight (a fight isn't saved; reloading restarts it from the scene before), and on death (the game returning to the menu) deletes the save only in «Одна жизнь» mode (`session.oneLife`, chosen at hero creation); otherwise the save still holds the last choice before death, since death scenes and fights aren't saved, so «Загрузить игру» returns there. Components read state with `useGameState()` and call store methods; they never mutate state. `App.tsx` renders the scene and hero panel with overlays for the menu, hero creation, the fight, the level-up reward and the journal. Player preferences that aren't part of a playthrough live in `settings.ts` (`useSettings()`, its own `localStorage` key `nightwatch-settings`), including which first-time hints were dismissed; `hints.ts` lists those hints (parry, retry, journal, roaming, bag) with the game state that triggers each, shown one at a time by `HintToast`. Sound is synthesized with Web Audio, no audio files: `soundCues.ts` decides what plays (pure and tested: ambience by place and time of day, cues from state changes such as a hit, a parry, a check result or a scene's `sound: 'horn'`), `audio.ts` synthesizes it once the player's first click or key press unlocks audio, and `useAudio` connects them; volume and on/off are in settings. `useKeyboard.ts` maps 1–9 to choices, 1–4 to level-up rewards, 1/2/3/4, Enter and Space to fight actions (4 is the first bag item), J (by `e.code`, so it works in the Russian layout) to the journal, M to the map, H to the chronicle (`chronicle.ts`: the last 50 scenes read, choices made and fight results of this browser session, kept in the store, not in saves; the journal and the chronicle switch to each other) and Esc to closing the open panel or opening settings (`SettingsView`: language, font size via `html[data-font]`, hints, exit to the menu, which keeps the save via `store.exitToMenu()`); it reads `store.getState()` at key time rather than the rendered state, so fast repeated presses don't apply a stale choice.

### Languages

Russian (primary) and English, no i18n library. The language is a player preference (`settings.language`, default `'ru'`, not in saves), switched in the main menu and in settings (`LanguageSwitch`), and applies at once, including to notices, the fight log and the chronicle already on screen. Components get everything through `useI18n()` (`src/ui/i18n.ts` → `i18n(lang)` in `src/i18n/index.ts`): `t` (UI strings), `name(s)` (a content name or title), `text(text, ctx)` (content text), `label(label, ctx)` (a choice's `Text` or `Message`), `msg(message)` and `time(minutes)`. Game view builders that resolve text (`journal`, `activeGoals`, `people`) take the translator `tr` as an optional argument; tests leave it out and get Russian.

- **UI strings and engine messages**: `src/i18n/ru.ts` is the template (`Dict = typeof ru`; parameterized strings are functions, Russian plurals included), `en.ts` is typed as `Dict`, so a missing or mistyped key doesn't compile. `msg` holds a format for every `Message` id (`MessageFormats`); a new message kind needs an entry in both. Hint texts are `t.hints[id]`.
- **Content**: stays in Russian in `src/content/`; the English translation mirrors it in `src/content/en/` by id and order (scenes: `{ title, text, choices: [...] }` with choice texts in the scene's order; journal notes in order; points of interest by key, with their actions in order (an action with a `disabled` reason is `{ text, disabled }`), routine activities by id; tables by id for classes, items, weapons, armors, stats, enemies; lists in order for attitudes and level rewards). An English text may be a function of the same context. `src/i18n/content.ts` walks the Russian content and its translation in parallel and looks translations up by the Russian text itself (string or function), so copied choices and enemy names in fights are translated too; identical Russian strings must translate identically. Text without a translation falls back to Russian, so a new scene can be written first and translated later, but `tests/i18n.test.ts` fails on missing translations, mismatched choice or note counts, translations of unknown scenes, and Cyrillic in English output (run over many flag, relation, time and place combinations).
- The debug panel stays in Russian.

### World and time

A session is either in a scene (`sceneId` set) or roaming a location (`sceneId === null`). Time is `session.time`, minutes since midnight of day 1 (`time.ts`: `atTime`, `toGameTime`, `inHours`; periods are morning 6–12, day 12–18, evening 18–22, night 22–6). The game starts at `START_SCENE` / `START_TIME` / `START_LOCATION` in `story.ts`.

While roaming, `roamGroups()` builds the choices in groups, shown under their headings (`roamChoices()` flattens them in the same order, which is the 1–9 key order): people (talks with NPCs whose `schedule` puts them here now; the talk choice's own `if` / `ifNot` / `ifRelation` still apply), points of interest, paths (exits to known places; an exit with `if` stays visible but disabled with its `locked` hint until the flag is set — soft unlocking) and time ("wait an hour" and, where `bed` is set, "sleep until morning", +1 HP per hour slept).

A location's `spots` are its points of interest (the window, the chest, the brazier): `{ name, text, image?, if?, ifNot?, hours?, actions }`. A spot is shown only while its conditions hold, so a hidden spot is one behind a flag another choice sets. Choosing it (`{ look }`) sets `session.spotId`: the screen shows the spot's name, text and image (or the location's), and the choices are only its `actions` plus "Отойти" (`{ back }`, also Backspace). Entering a scene, moving or loading a save clears `spotId`; it isn't saved. `session.visited` lists locations and spots (`'cell.window'`) the hero has been to; unvisited spots carry a «новое» tag and unvisited places a mark on the map. A choice with `hours` and `showClosed` (the routine activities) stays visible outside its hours, disabled with the hours as the reason, instead of disappearing.

The fortress map (`src/game/map.ts`, `MapView`, the M key or the button under the journal's) draws locations that have a `map: { x, y }` position (0–100 × 0–70) and are known (`known`: a `Condition`, known by default; an unknown place is on neither the map nor the exits list), the roads between them from their exits (dashed unless open both ways), where the hero is, which known NPCs are where right now, travel time and the `locked` hint of a closed way. Clicking a reachable place while roaming chooses `{ travel }`: the hero walks the fastest open route (`route()`) place by place, time passes per step, and an event in a place on the way stops the walk there. Story events (`events.ts`) start a scene by themselves when the hero is in their `location` within their `hours` (plus `fromDay`, `if`, `ifNot`); each fires once (`session.events`) and only while roaming. Waiting and sleeping advance time in 15-minute steps aligned to the quarter hour and stop when an event starts; moving checks events on arrival. A choice with `daily: 'training'` can be taken once per game day (afterwards it shows disabled until the next day; `session.daily` stores the day each was last done), and `xp: N` grants XP on pick; the fortress routine (training, kitchen, the brazier, ash) is built this way in `src/content/chapters/routine.ts` (`ROUTINE` by activity id) and placed at points of interest in `locations.ts`. Scenes can set `location` (entering moves the hero there) and `set` (flags recorded on entering). Text functions also get `time` and `location`, so a scene can read differently by hour or place.

### Journal

The journal (`src/content/journal.ts`) lists goals and leads. It isn't stored: `journal(session)` rebuilds it from flags and fired events. An entry appears when its condition holds (`if`, `ifNot`, `event`), shows the `notes` whose conditions hold, is done when `done` holds, and a goal that isn't done shows its `hint` (also shown under the journal button in the hero panel for the first active goal). `choose` and `closeFight` compare the journal before and after and add notices ("new goal", "new lead", "new entry", "goal done"); a new game starts with one. To make progress visible in the journal, set a flag in the story and reference it from an entry; `tests/story.test.ts` checks that every flag a journal condition uses is set somewhere. Entries are written in the first person, as the hero's notes.

### Relations

Each NPC has an attitude towards the hero, `session.relations[npcId]`, from −5 to 5 (0 when never changed; limits and attitude names such as «симпатизирует» are in `src/content/relations.ts`). A choice's `relation: { vasya: 1 }` changes it on pick, `check.relation` only on success and a scene's `relation` on entering it; every change that isn't clamped away adds a notice ("Вася: отношение улучшилось"). `ifRelation: { npc, min?, max? }` shows a choice only within that range, so one line can lead to different scenes by attitude (see Torvin and the forest lights), and text functions can read `relation(id)`. Give relation changes only to choices that can't be repeated (guard them with a flag), or they can be farmed. An NPC's `known` condition and `about` text put them in the journal's «Люди» section with their attitude.

### Scenes

A scene is `{ image, actor?, title, text, choices }`. `image` (like a location's) may be a function of the same context as text: chapter 1's `HERE` shows the picture of wherever the hero is, for talks that happen in more than one place. `text` and choice `text` are a string or a function of `{ hero, flag, time, location, relation }`; `\n` renders as a line break. Choices are a union discriminated by which key is present (engine checks with `in`):

- `{ next }`: go to a scene.
- `{ fight: EnemyDef, next }`: fight; winning goes to `next`. After a loss the player can «Попробовать снова» (`retryFight`: back to the session as it was before the fight choice, kept in `fight.retry`) or give up, which is game over; in «Одна жизнь» mode a loss is always game over. Take enemies from the bestiary (`ENEMIES.vasya` in `src/content/enemies.ts`) so the balance tool sees them. `EnemyDef` has `hp` (default 10), `damage` (default 0–2), `xp` (default `FIGHT_XP`, 10, granted when the win is closed), `windup` (the chance the enemy winds up instead of striking; the next strike is doubled), `armor` (subtracted from each hero strike except precise ones) and `dodge` (the chance to evade a plain strike, not a special).
- `{ check: { stat, difficulty, set?, give?, xp? }, next, fail }`: a stat check. The chance is 50% + 15% per point above `difficulty`, clamped to 5–95%, and is shown on the button. `check.set`, `check.give` and `check.xp` (default `CHECK_XP`, 5) apply only on success. Results, loot and XP gains are `session.notices`, shown above the next scene's text and cleared by the next choice.
- `{ leave: true | LocationId }`: end the scene and roam here (or at that location).
- `{ move }`, `{ travel }`, `{ look }`, `{ back }`, `{ wait }`, `{ sleep }`: generated for roaming; not normally written in scenes.
- `{ gameOver: true }`: game over. A scene containing one is a death scene and is never saved.
- No action: the choice does nothing (for example, the end of written content).

Any choice may also have `set` (flags recorded on pick), `if` / `ifNot` (show only when a flag is or isn't set), `relation` / `ifRelation` (see Relations), `heal: N` (restore up to N HP, capped at max) `give: { weapon?, armor?, items? }` (a weapon or armor is equipped at once, items go to the bag), `minutes` (time the choice takes, default 0), `hours` (shown only within these hours; with `showClosed`, shown disabled outside them) and `disabled` (shown but not selectable, with the reason). Scene ids are plain strings unique across chapters; `tests/story.test.ts` checks that every link target exists, every scene is reachable, every image file exists in `public/` and every flag used in `if` / `ifNot` (in choices, exits and events) is set somewhere, every event scene exists and exits are two-way. Reachability counts the prologue, event scenes, NPC talks and actions at points of interest as entry points.

### Combat

Each round the player attacks, uses a bag item (`{ item }`: bread heals and the enemy still answers; an item with `stun`, like ash, makes the enemy skip its answer and lose its wind-up; `itemBlocked` says when an item can't be used, e.g. ash outside a fight), defends (halves incoming damage, doubles dodge; against a wound-up heavy strike it parries: no damage and a counter strike) or uses the class special (`HeroClass.special`: a `damage` multiplier, `stun` so the enemy skips its answer and loses its wind-up, `crit` for a guaranteed crit, and a `cooldown`). Hero damage is strength plus a weapon roll, doubled on a crit. Crit and dodge chances (`combatStats`) are the class's plus `CRIT_PER_WITS` / `DODGE_PER_AGILITY` per point of wits / agility above the class's starting value, capped at `MAX_CHANCE` (`src/content/combat.ts`). The hero's armor (`armorId`, `src/content/armors.ts`: the jacket Torvin gives when he likes the hero) is subtracted from each enemy strike before defending halves it. Hero HP carries over between fights; `heal` choices, items and level-ups restore it. The order of rolls in a round is documented on `playRound`; combat tests depend on it.

The balance tool (`src/game/balance.ts`, shown by the debug panel's «Баланс боя») plays many fights of preset heroes and the current hero against every bestiary enemy with a strategy («с умом»: parry, eat at low HP, use the special; or attacks only) and reports win rate, fight length and HP lost. `tests/balance.test.ts` pins thresholds (chapter 1 fights winnable by any level-1 hero, chapter 2 enemies by a level-1 hero with a knife who plays well, classes within 15% of each other); after changing combat numbers, check the table and keep those tests passing.

### Progression

XP comes from fights and successful checks; `addXp` raises `level` by the `LEVEL_XP` thresholds and adds one `levelUps` per level gained. While `levelUps > 0` (and not fighting) the story is paused behind the level-up overlay: `chooseLevelReward` applies +1 to a stat or +3 max HP from `LEVEL_REWARDS` and fully heals.

### Saves

`localStorage` key `nightwatch-save`, format version 11: `{ version, sceneId, locationId, time, events, hero, flags, relations, oneLife, daily, visited }`. Besides the autosave there are three manual slots (`SaveSlot`: `'auto' | 1 | 2 | 3`, keys `nightwatch-save-1…3`), written from the settings screen (not during a fight or in «Одна жизнь» mode) and listed with hero, place, game time and `savedAt` (optional, missing in older saves) by «Загрузить игру»; «Продолжить» in the menu loads the autosave. `migrate()` upgrades step by step: version 2 (the pre-TypeScript game: `stage`, `class: 'Warrior'`, `src`, `hp`/`currentHp`) → 3 → 4 (adds `inventory`, `xp`, `level`, `levelUps`) → 5 (adds location, time and fired events, reconstructed from the scene the linear chapter stopped at) → 6 (sets the `joined` flag, which the journal's first goal needs, for saves past the prologue) → 7 (adds relations, reconstructed from chapter 1 flags and events) → 8 (adds `oneLife`, false for old saves) → 9 (adds `daily`, empty) → 10 (adds `hero.armorId`, `'none'`) → 11 (adds `visited`, just the current location). Saves with an unknown scene, location, event, NPC, class, weapon, armor or item are ignored. When the save format changes, bump `SAVE_VERSION` and add a migration step instead of breaking old saves.

## Assets and design

Images live in `public/img/` and are referenced by relative paths such as `'img/scene-hall.jpg'`; hero portraits are stored in saves this way. Images are AI-generated from the prompts in `docs/image-prompts.md`, which also defines the shared style suffix and negative prompt; keep new art consistent with it (scenes 16:9 at 1344×768, portraits 1:1). The user's full-size PNG originals are in `img-source/`, which is git-ignored. The game uses JPG copies, with portraits downscaled to 512×512. A missing image is hidden rather than shown broken (`Picture` component), so scenes can be written before their art exists.

The UI is a dark theme matching the art. Colors and fonts are CSS variables on `:root` in `src/styles/main.css` (Cormorant SC and PT Serif from Google Fonts, with Georgia as fallback). Below 760px the layout switches to one column with the hero panel as a compact bar on top.

`docs/1 глава.txt` holds the chapter 1 premise, and `docs/Структура.docx` plans the chapter's locations (outside the fortress → inner courtyard → room 1 → chamber).
